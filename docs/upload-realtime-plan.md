# แนวทางทดลองอัปเดตสถานะอัปโหลดแบบ realtime

เริ่มที่ Upload Studio และหน้าคิว เพื่อลดการอ่านสถานะซ้ำจาก Neon ระหว่าง GitHub Actions ทำงาน

1. ตอนเปิดหน้า โหลดสถานะล่าสุดจาก API
2. เมื่อสถานะงานเปลี่ยน ให้ GitHub Actions ส่ง HTTPS POST ไปยัง backend ส่งเปอร์เซ็นต์เป็นระยะประมาณ 5–10 วินาทีขณะมีงาน และส่งสถานะเสร็จหรือล้มเหลวทันที
3. Backend ส่ง event ขนาดเล็กให้หน้าเว็บผ่าน WebSocket (`wss://`) ผูก event กับ `videoId` และตรวจสิทธิ์เข้าถึงงานก่อน subscribe
4. หลัง reconnect ให้โหลดสถานะล่าสุดจาก API เพื่อเก็บช่วงที่พลาด และโหลดซับเมื่อพร้อมหรือเปลี่ยน

ใน Studio แสดงขั้นตอนของงานแปลงวิดีโอ ถอดเสียงและแปลซับ และสร้างภาพตัวอย่างแยกกัน งานที่ยังวัดเปอร์เซ็นต์ไม่ได้ให้แสดงชื่อขั้นตอนกับเวลาที่รอ หน้าคิวแสดงสถานะย่อ ส่วน log ละเอียดดูใน GitHub Actions

ก่อนเปลี่ยนเป็นค่าเริ่มต้น วัดจำนวน query และปริมาณข้อมูลที่ Neon ส่งออก รวมถึงจำนวนข้อความและการ reconnect ฝั่ง Vercel ทดสอบเวลาจากกดเล่นถึงเฟรมแรกกับเส้นทาง HLS เดิมด้วย การลด egress จากการอุ่นแคชใน Feed เป็นงานอีกส่วนหนึ่ง

เมื่อพร้อมขึ้น Git ให้แยก commit ของ realtime ออกจากงานแก้ซับต้นฉบับปนไทยเพื่อให้ตรวจได้ทีละเรื่อง
